# ASC 元数据清单与填写顺序

以 App Store Connect 中文界面为准。按此顺序填，每步保存后重载复核。

## 1. 版本页（分发 → iOS App 版本 X.Y）

| 字段 | 说明 | 坑 |
| --- | --- | --- |
| 推广文本 | 170 字符上限，可后续随时改 | 可留空 |
| 描述 | 4000 字符上限 | 首段最重要（搜索折叠前可见） |
| 关键词 | 100 字符，逗号分隔不带空格 | 不要重复 App 名/类别词 |
| 技术支持网址 (URL) | 指向支持页 | 必须公网 200 |
| 营销网址 (URL) | 可填官网首页 | 可留空 |
| 版本 | 如 1.0 | 与构建 MARKETING_VERSION 一致 |
| 版权 | 如 `2026 Chao Wei` | 年份 + 权利持有人 |
| 构建版本 | 点「选取构建版本」挂已上传构建 | 构建处理完（约几分钟~半小时）才可选；挂完必须再点页面「保存」 |
| App 审核信息-联系信息 | 姓名 / 邮箱 / 电话 | **电话必须带 `+` 国家码**，否则保存报错 |
| App 审核信息-备注 | 给审核员看的说明 | 写清核心功能、无账号体系、测试路径 |
| 需要登录 | App 无账号体系时**取消勾选** | 默认可能勾选，勾了又没给凭据会阻塞 |
| 附件 | 可空 | |
| 版本发布方式 | 手动 / 自动 / 定时 | 手动 = 过审后需再点一次「发布」才上架 |

## 2. 截图（版本页 → 预览和截屏 → 媒体管理）

- 必需：`iPhone 6.9 英寸` 槽 + `iPad 13 英寸` 槽（支持 iPad 的 App），各最多 10 张。
- `6.5 英寸 iPhone` 自动继承 6.9" 素材，无需单独传。
- 6.9" 槽默认折叠成手风琴，**先点开展开**再拖拽/选取文件。
- iPad 截图：媒体管理页顶部「iPhone」下拉切到 iPad。
- 只有前 3 张用于 App 安装表——最重要的画面放前面。
- 上传后回版本页确认槽位计数（如「8/10 张截屏」）并保存。

## 3. App 信息（侧栏 App 信息）

- 副标题（30 字符）
- 主要类别（如「软件开发工具」）+ 次要类别（如「效率」）
- 第三方内容声明
- 年龄分级：分步问卷（功能/App 内控件组 + 频率题组），**最后一步用问卷自己的「下一步」走到系统计算结果页（如 4+）再保存**；在倒数第二步点页面级「保存」会丢进度。

## 4. App 隐私（侧栏 App 隐私）

1. 隐私政策网址（公网 200，内容含联系方式）。
2. 数据收集问卷：零收集选「否，我们不会从此 App 中收集数据」。
3. **点页面顶部「发布」，并在确认弹层「是否发布你的 App 隐私答复？」中确认**。
   - 「保存」只存草稿；页面显示「几秒钟前由 X 发布」才算完成。
   - 不发布就提交审核，必报：「具有"管理"职能的用户必须在"App 隐私"部分提供相关信息」。
   - 问卷弹层里答案没变化时「保存」按钮是灰的——这是正常状态，说明服务端已是该答案，不需要强行改动。

## 5. 定价与供应情况（侧栏 定价与供应情况）

- 价格时间表：选价格等级（免费 = $0.00，按基准地区如美国设），保存后重载复核。
- 分发方式：选「公开 — App Store 上对所有人可见」。
- 供应情况：确认国家或地区列表（默认全部 175 个），点确认保存。
- 「请选择你希望以何种方式向用户分发 App」是常驻说明文字，**不是报错**。

## 6. 提交（版本页）

1. 右上「添加以供审核」→ 服务端校验，缺什么列什么，逐项清。
2. 校验通过后出现「草稿提交 (1)」区 → 点「提交以供审核」。
3. 成功标志：页面提示「已提交 1 个项目」，状态变「正在等待审核」；重载页面再确认一次。
4. 提交后大部分元数据锁定，要等审核结束或手动「从审核中移除」才能改。
